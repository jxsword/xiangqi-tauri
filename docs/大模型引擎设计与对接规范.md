# 大模型引擎设计与对接规范

> 本文档记录"中国象棋 Tauri"中 AI 走子的完整设计：内置引擎与大模型的配合方式、
> 客户端请求提示词、大模型请求参数的注意事项、返回数据校验过滤链，
> 以及本项目中踩过的坑与修复结论。**其他技术栈（如 Flutter/Electron）实现相同功能
> 可直接参考本节经验，避免重复犯错。**

---

## 1. 架构总览：内置引擎与大模型的配合

```
                      ┌────────────────────────────┐
   对局轮转(GameLoop) │ Engine trait（统一走子接口） │
                      └────────────┬───────────────┘
                                   │ 由对局模式决定当前轮方使用哪个引擎
              ┌────────────────────┼─────────────────────┐
              ▼                    ▼                     ▼
      BuiltinEngine          LlmEngineAdapter      HumanInput(前端)
   (xiangqi-search，         (llm-engine crate，     (点击棋盘走子)
    UCCI 协议，可配深度)       OpenAI 兼容客户端)
```

- **引擎抽象**：`Engine trait` 是唯一入口（`best_move(board)`），内置引擎与大模型引擎
  平级实现。上层（对局模式、UI）不感知具体实现，只需处理 `Ok(着法)` 或 `Err(原因)`。
- **降级策略**：`LlmEngineAdapter::best_move` 中，大模型返回 `Err`（超时/网络/非法着
  超过重试上限）时，**自动降级到内置引擎**走子，并把原因（如"着法非法：b7e7"）透出
  给 UI 展示。用户看到"⚠️ 大模型不可用（原因），已由内置引擎走子"即由此而来。
- **引擎归属由模式强制**（`new_game` 命令）：人机对战 → 红方为人类、黑方为所选引擎；
  机器对战 → 双方引擎；内置引擎可配速度档位（深度 2/3/6 + 思考毫秒数）。

## 2. 客户端 → 大模型：请求提示词

### 2.1 请求端点与参数（OpenAI 兼容 Chat Completions）

```
POST {base_url}/chat/completions
Authorization: Bearer {api_key}
Content-Type: application/json
```

请求体（关键参数及**为什么**）：

| 参数 | 值 | 说明 / 注意事项 |
|---|---|---|
| `model` | 如 `qwen3.8-max` | 可配置 |
| `messages` | system + user（见 2.2） | 不要放太长历史，象棋只需当前局面 |
| `temperature` | `0.2` | 偏低求稳定，避免模型随机乱走 |
| `max_tokens` | `512` | **不要设太小（如 64）**：若模型带思考链，思考 token 计入其中，会占满上限导致着法缺失 |
| `stream` | `true` | **必须流式**。非流式=服务端完整生成后才返回响应头，配合超时包 `send()` 会导致"明明能答却超时"（见 §5 踩坑 1） |
| `enable_thinking` | `false` | **qwen3 系列默认开启思考链**，长思考拖慢响应；象棋着法不需要思考链，必须显式关闭（若模型不支持该参数，服务端一般忽略或报 400，需按模型调整） |

### 2.2 提示词原文（当前版本，经实测调优）

**system**（要点：坐标规则 + few-shot 示例 + 硬性约束）：

```
你是中国象棋引擎，只能输出一步着法。
坐标规则：UCCI 记法为 4 字符，前两字符为起点、后两字符为终点；文件 a-i 从左到右（红方视角），行 0-9 从红方底线到黑方底线。
示例：FEN: rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w，红方最佳着法为 b2e2（炮二平五）。
硬性要求：1) 起点必须是你方棋子所在的格子；2) 整着必须符合中国象棋规则（兵卒只能前进、炮翻山吃子、马蹩脚、车走直线、相/仕不出九宫等）；3) 只能输出一步着法，仅 4 个字符，禁止任何解释、标点或额外文字。
```

**user**：

```
FEN: {fen}
轮走方: {side}
请给出最佳着法。
```

- `fen` 来自 `board.to_fen()`，已确认与标准 UCCI 坐标系一致（段 1 = rank 9 黑方底线 … 段 10 = rank 0 红方底线）。
- **提示词注意事项（经验）**：
  - 必须给 few-shot 正确示例——纯规则描述时，模型会幻觉坐标（实测初始局面它答对 `b2e2`，但中局经常给出起点无子/路径非法的着法如 `b7e7`）。
  - 明确"起点必须是你方棋子所在格"能显著减少"走对方棋子"类错误。
  - 禁止解释/标点，否则解析噪音大（虽有容错提取，但越干净越好）。

## 3. 大模型 → 客户端：返回解析

### 3.1 流式（SSE）响应

```
data: {"choices":[{"delta":{"content":"b"},"finish_reason":null}]}
data: {"choices":[{"delta":{"content":"2e2"},"finish_reason":null}]}
data: {"choices":[],"usage":{...}}
data: [DONE]
```

解析要点：
- 按 `\n` 分行，取 `data:` 前缀后的 JSON，累加 `choices[0].delta.content`；
- 遇到 `[DONE]` 或流结束返回拼接结果；
- 判断是否流式：`Content-Type` 含 `text/event-stream`；
- **非流式回退**：服务端不支持流式时返回普通 JSON（`choices[0].message.content`），两种格式统一处理后端。
- qwen 类模型思考内容在 `delta.reasoning_content`（不参与着法提取，Serde 忽略即可）。

## 4. 返回数据校验过滤链（防"大模型乱走"的关键）

```
模型回复文本
   │  ① extract_ucci：正则式提取首个 [a-i][0-9][a-i][0-9] 4 字符子串
   ▼          （容忍前后有解释文字，但提示词已要求禁止）
UCCI 字符串
   │  ② Move::from_ucci：解析为内部着法结构（失败=格式非法）
   ▼
Move
   │  ③ legal.contains(&mv)：必须在本方合法着集合内
   ▼
合法？ ──是──▶ 落子
   │否
   ▼
二轮纠错：把当前局面【全部合法着清单】发给模型，
          "请只从中选择一步并仅输出 4 字符 UCCI"
   ▼
再次执行 ①②③；仍非法 → 返回 Err，上层降级内置引擎并展示原因
```

- **为什么二轮要"给清单"而不是"再让模型想"**：首轮失败已证明模型在当前局面下
  坐标推演不可靠，再说一次"请输出合法着法"结果一样；把合法着列成候选清单，
  把任务从"自由推演"降级为"做选择题"，命中率接近 100%（仍过 `legal.contains` 兜底）。
- **校验顺序不能省**：UCCI 格式 → 坐标解析 → 合法着集合。任何一步失败都不得落子。
- 合法着清单来自 `board.legal_moves()`（引擎侧已过滤"走后送将"等），token 成本约百级，仅在重试时产生。

## 5. 踩坑记录（错误 → 根因 → 修复）

1. **"下棋一直超时降级，但测试连接正常"**
   - 现象：人机对战每步都提示"请求超时（>30s）"，降级内置；测试连接却秒成功。
   - 根因：请求是**非流式**，超时包在 `send()`（等响应头）上；非流式 = 服务端完整生成后才发头。
     qwen3 默认思考链长，30s 内生成不完 → 超时。测试连接是短请求所以快。
   - 修复：`stream: true`（头即时返回，边生成边收）+ `enable_thinking: false` + `max_tokens` 提到 512。
   - **其他技术栈参考**：只要接大模型，优先流式；超时语义要按"首 token/块间隔"设计，不要等完整 body。

2. **"模型经常返回非法着法"**
   - 现象：初始局面能答对，中局频繁给出起点无子/路径非法的着法（如 `b7e7`）。
   - 根因：大模型对"严格坐标推演"能力不稳（幻觉），纯规则提示词约束不住。
   - 修复：提示词加 few-shot 正确示例 + 硬性约束；**二轮改为给出完整合法着清单让模型选择**。
   - **其他技术栈参考**：任何"LLM 下棋/LLM 输出结构化决策"都建议（a）few-shot；（b）输出后
     用确定性代码校验（本项目的合法着集合）；（c）失败重试时给候选集而非重问。

3. **"重启后 apiKey 看起来丢失"**
   - 现象：重启后 API Key 输入框空白，以为配置丢了。
   - 根因：配置已持久化到 `~/.local/share/{identifier}/llm-config.json` 且启动自动加载；
     但前端密码框**不回填**（安全设计），且空 key 点保存会用空值**覆盖**已存密钥。
   - 修复：密码框 placeholder 提示"已保存，无需重复输入"；`set_llm_config`/`test_llm_config`
     收到空 api_key 时**沿用内存中已存密钥**；配置文件写入后 `chmod 600`（Unix）。

4. **"人走一步很卡，棋盘不刷新直到机器落子"**
   - 根因：`machine_step` 是同步 Tauri 命令，LLM 请求（最长数秒）阻塞命令线程 → UI 冻结。
   - 修复：`machine_step`、`test_llm_config` 改为 `async fn`（Tauri 异步命令在线程池执行）。
   - **其他技术栈参考**：任何可能耗时 >100ms 的命令（LLM/网络/重计算）必须异步化，
     前端先更新本地状态（"思考中…"），再等异步结果回填。

5. **"测试连接报 401 You didn't provide an API key"**
   - 根因：密码框不回填，测试按钮把空 apiKey 直接传给后端。
   - 修复：`test_llm_config` 同样做"空 key 沿用已存密钥"。
   - 教训：前端隐藏字段（密码框）≠后端无值；所有用到该字段的命令都要有"空值回退"策略。

6. **配置持久化位置**
   - 使用 Tauri `app_data_dir()`（Linux `~/.local/share/com.xiangqi.app/`），**不写安装目录**
     （用户可写/权限/卸载保留）；与存档 `saves/` 同级。
   - 启动时 `setup` 加载并写入全局 `AppState.llm`，各命令共享。

## 6. 其他技术栈（如 Flutter）实现要点速查

实现"大模型下棋"时按此清单核对，可避免本项目踩过的所有坑：

- [ ] 走子决策走 `Engine` 抽象，内置引擎与 LLM 引擎可互换、可降级
- [ ] 请求用 **流式（SSE）**，不要非流式等完整生成
- [ ] qwen3 系显式 `enable_thinking=false`；`max_tokens` ≥ 256（防思考占满）
- [ ] 超时**可配置**（本项目 5–120s，默认 30），按"分块读取"而非"等完整响应"计时
- [ ] 提示词含 few-shot 正确示例 + "起点必须是你方棋子"等硬性约束 + "只输出 UCCI"
- [ ] 输出必经**确定性校验链**：格式 → 坐标解析 → 合法着集合
- [ ] 失败重试给**合法着候选清单**（选择题），不要重复让模型自由发挥
- [ ] 网络/LLM 命令**异步化**，前端先更新"思考中"状态
- [ ] 配置持久化到**应用数据目录**，启动恢复；空密钥不得覆盖已存密钥；密钥文件收紧权限
- [ ] 测试连接与真实走子用**同一套参数与超时**（否则出现"测试通过、实战超时"的假象）

## 7. 引擎参谋制（v2，当前实现）

### 7.1 设计不变式（改动任何一条，合法率都会崩）

1. **大模型只提议，本地规则是唯一事实源**：客户端先用本地棋规/引擎生成决策池
   （candidate 模式=引擎 Top-K 短名单；off/gate=全量合法着），发给 LLM 的清单条目
   与期望输出**完全同构**（`h2-e2`）——模型只需"复制选择"，不需"换算生成"。
2. **每次请求只有 system+user 两条消息**：重试不是多轮对话累积，而是把失败反馈
   **追加到 user 文本末尾后重发**。
3. **流式 SSE + 空闲超时**：超时定义为"两次数据块的最大间隔"（默认 30s，
   总耗时上限 = 空闲超时 × 4）；思考型模型持续吐字不会被误判超时。
4. **兜底链永不卡死**：重试耗尽 → 内置 AI 代走；引擎护航否决 → 带理由再问一次 →
   仍不行由引擎最佳代走。**"参谋否决代走"与"模型失败降级"是两条不同路径**，
   透出 UI 的文案分开标注。

### 7.2 三种参谋模式（`LlmConfig.advisor` + `blend` 0–100）

| 模式 | 决策池（白名单） | 引擎职责 | blend 作用 |
|---|---|---|---|
| `off` | 全量合法着清单（v2 基线，无分档） | 无 | 不适用 |
| `candidate`（默认） | **引擎 Top-K 短名单**（K = 3 + blend/20，即 3–8 条），清单每条附「—」引擎分档 | 出短名单 | K 随 blend 增大 |
| `gate` | 全量合法着清单自由选 | 对所选着法单独评估，分差超阈值**一票否决**，带理由再问一次 | 否决阈值 = 80 + 3.2×blend 厘兵；blend=100 时不否决 |

实现位置：`game-core/src/engine.rs` → `LlmEngineAdapter`（`move_candidate` / `move_gate`），
按 `self.client.config().advisor` 路由；`game.rs` 走子调用
`engine.best_move_with_history(board, opts, self.moves())` 传入历史。

### 7.3 单着完整决策流程

```
轮到 AI 走棋
 ├─ advisor=off → 全量合法清单（无分档）→ LLM 选择 → 白名单校验
 ├─ advisor=candidate：
 │    引擎 top_moves(board, K=top_k(), ms=think_ms.max(800), depth=4)   ← 根节点全窗口搜索
 │    → 候选池 = Top-K 短名单（附真实分差）→ Prompt v2(带分档) → LLM
 │    → 解析提取 → 校验 ∈ 候选池（≤3 次尝试）→ 失败降级内置
 └─ advisor=gate：
      引擎 top_moves(board, 8, ms) 拿 best_ucci + best_score（真实分差）
      → 全量清单 Prompt v2（无分档）→ LLM 选择 mv
      → evaluate_move(mv, depth-1) 复评；loss = best_score - mv_score
      → loss ≤ 阈值(80+3.2×blend) → 采纳
      → loss > 阈值 → 带【参谋否决】理由再问一次
          → 第二次着法复评仍超阈值 → 引擎最佳着法代走（note=参谋否决）
          → 第二次着法 ≤ 阈值 → 采纳改选（note=参谋否决后改选）
      → 模型请求失败 → 内置代走（note=大模型不可用，与参谋否决分开标注）
```

要点：
- 引擎搜索用**根节点全窗口**（`Searcher.root_scores`，不剪枝）拿到的分数才是真实分差，
  否决阈值才有意义；普通 αβ 剪枝返回的边界值不能用于算 loss。
- 否决后再问时，**对第二次选择重新评估**（不是信第二次的回答），仍超阈值才动用引擎最佳。
- 历史着法（UCCI，旧→新，最多 60 着）与循环警示（最近 4 着呈 A→B、C→D、B→A、D→C
  往返）会写入 user 文本，引导模型打破循环（长将/长捉判负的预防提示，不做规则判定）。

### 7.4 Prompt v2（逐字）

**system（每次请求相同，仅执方不同；candidate 模式带分档引导句）：**

```text
你是中国象棋对弈引擎的着法接口，本局执红方或黑方。
坐标约定：列用字母 a-i（从左到右，红方视角），行用数字 0-9（0 为红方底线、棋盘底部，9 为黑方底线、棋盘顶部）。着法格式为「起点-终点」，如 h2-e2。
你只能从用户提供的「候选着法清单」中选择一步，禁止编造清单之外的着法。
【回复格式（唯一允许的格式，共两段）】
第一段以「分析:」开头，用一两句话（不超过 100 字）说明你的计划（进攻目标、需要提防的威胁）。
最后一段为一行，形式为：
着法: 起点-终点
示例：着法: b2-e2
候选着法清单中每条着法附有「—」后的引擎评估分档，请优先考虑评估为「最佳/均势」的着法，避免选择「大亏/致命」档的着法。
```

**user（每手动态组装）：**

```text
【当前局面 FEN】rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1
【棋盘图】
    a b c d e f g h i
0  R N B A K A B N R
1  . . . . . . . . .
...
9  r n b a k a b n r
【轮走方】红方（该方是你）
【对局着法（最新在最后）】h2-e2 e7-e5 ...
【候选着法清单（共 5 条，由本地引擎选出，必须从中选择一条；「—」后为引擎评估分档）】
h2-e2(将军) — 最佳/均势
h0-g2 — 最佳/均势
e3-e4 — 略亏
【输出】先输出「分析:」段，最后一行输出「着法: 起点-终点」
```

- 棋盘图为 10 行 ASCII：红大写/黑小写（FEN 字母），行号 0-9 与坐标一致（0 在底部=红方底线）。
- 清单行注解（吃子子名、将军标记）与分档**全部由本地规则+引擎生成，零幻觉**。
- 检出循环时在清单后追加一行：【警示】最近着法出现来回重复。长将/长捉判负，重复局面会被视为无效——请选择打破循环的着法。
- gate 否决再问时追加：【参谋否决】你上一次选择的 {mv} 会被引擎惩罚（{分桶}，相对最佳损失 {loss} 厘兵）。请重新从候选清单中选择……

**分桶（相对最佳分差 loss，厘兵）：** ≤30 最佳/均势；≤100 略亏；≤250 明显亏（约半子）；≤600 大亏（丢一马/一炮级）；>600 致命（丢车/被将杀级）。

```http

### 7.6 返回数据五层过滤 + 第六层双保险

```
SSE 字节流 → 按行切分
 L1 流重组：丢空行/`:`注释心跳（如 PROCESSING）；data:[DONE] 结束；chunk 含 error 字段 → 计失败
 L2 文本提取：正文非空取正文；正文为空（思考型 token 耗尽）退回思维链文本尽力提取
 L3 归一化：剥 ``` 代码围栏 → 删零宽字符(\u200b-\u200f/\uFEFF/\u2060) → 全角 ASCII 区(0xFF01-0xFF5E)
            逐字符平移回半角(-0xFEE0) → 转小写
 L4 坐标提取：([a-i])(数字)[可选分隔符 - – — ~ 到 至]?([a-i])(数字)
            「着法:」标记后第一个坐标对优先；否则取最后一个坐标对（总结论常在末尾）
 L5 白名单校验：归一为 4 字符 UCCI（h2e2）后与决策池精确匹配；不匹配 → 追加反馈重试（默认共 3 次）
 L6 playMove 最终校验（双保险）→ 落子
```

解析器实现：`llm-engine/src/lib.rs` → `normalize()` + `extract_move_v2()`。

**踩过的坑（务必记住）：**
1. **字节索引 vs 字符索引**：`String::find("着法")` 返回**字节**偏移，而解析用 `Vec<char>` 的
   **字符**索引——中文占 3 字节，两者错位会导致"着法:"标记优先失效、误取最后一个坐标对。
   修复：`chars.iter().position(|c| *c == '着')`。
2. **全角字符**：模型爱输出全角冒号/减号（着法：ｂ２－ｅ２），必须在提取前归一化。
3. **代码围栏**：模型常把答案包进 ```，不剥掉会解析失败。
4. **系统代理劫持本机测试**：WSL 环境变量 `http_proxy` 会劫持 reqwest 对 127.0.0.1 的连接
   （NO_PROXY 通配符不生效）——集成测试用 `LlmClient::new_no_proxy`（生产保留代理能力）。

### 7.8 其他技术栈实现要点速查（v2 增量）

- [ ] 决策池=本地生成的**白名单**，清单条目与期望输出同构；模型只能"复制选择"
- [ ] 每次请求 system+user 两条消息；失败把反馈**追加到 user 末尾**重发，不累积多轮
- [ ] 流式接收 + **空闲超时**（分块间隔），不是"等完整响应"的总超时；总上限 ×4
- [ ] 归一化五层过滤一个不少（全角/围栏/零宽字符是真实踩过的坑）
- [ ] 参谋评分必须**根节点全窗口搜索**（真实分差）；剪枝边界值不能用于否决阈值
- [ ] 否决后再问时**重新评估第二次选择**，不能信第二次的回答；"参谋否决代走"与
      "模型失败降级"分开标注（note/fallback_reason 语义不同）
- [ ] 历史着法与循环警示进提示词（预防长将/长捉的无效重复）
