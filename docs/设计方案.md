## 2. 棋盘与规则核心（xiangqi-core）

### 2.1 坐标与索引
- 棋盘 9 列 × 10 行 = 90 个交叉点。
- 一维索引：`sq = rank * 9 + file`（0..90）。
- **rank 0 = 红方底线（下方），rank 9 = 黑方底线（上方）**；file 0..8 从左到右为 a..i（红方视角）。
- UCCI 走法串：4 字符 `file_from rank_from file_to rank_to`，如 `h2e2`。file→字符 `a+i`，rank→数字 `0-9`。

### 2.2 数据类型
```rust
pub enum Color { Red, Black }          // 红先
pub enum PieceKind { King, Advisor, Elephant, Horse, Rook, Cannon, Pawn }
pub struct Piece { pub kind: PieceKind, pub color: Color }

pub const BOARD_SIZE: usize = 90;
pub struct Board {
    pub pieces: [Option<Piece>; 90],
    pub side_to_move: Color,
}
```

### 2.3 核心功能（全部纯函数/方法）
| 功能 | 说明 |
|---|---|
| `start_position() -> Board` | 标准初始局面 |
| `parse_fen / to_fen` | 中国象棋 FEN（如 `rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1`） |
| `pseudo_legal_moves(board) -> Vec<Move>` | 按兵种生成（含马腿/象眼/九宫/过河兵/将帅对面/炮隔子/车路） |
| `legal_moves(board) -> Vec<Move>` | 过滤自陷将军（走后本方被将军） |
| `is_in_check(board, color) -> bool` | 将军检测（含将帅互见） |
| `apply_move / undo_move` | 走子/悔棋（不可变风格：apply 返回新 Board，配 zobrist 可选） |
| `game_status(board) -> GameStatus` | Ongoing / Check / Checkmate(winner) / Stalemate(困毙) |
| `is_draw(board, move_count, repetition)` | 阶段一：自然限着 60 回合（120 步）判和 |

**Move 结构**：`struct Move { pub from: u8, pub to: u8 }`，`to_ucci()/from_ucci()` 转换。

### 2.4 单测覆盖（清单）
兵种走法边界（马腿、塞象眼、兵未过河不能横走、炮需炮架、车马炮将帅九宫限制）、将帅见面非法、送将非法、FEN 往返、将军/将死/困毙判定、起始局面 44 种走法（实测校准）、自然限着。

## 3. 内置搜索引擎（xiangqi-search）

```rust
pub struct SearchConfig { pub max_depth: u8 }        // 1..=6，对应难度档
pub struct SearchReport {
    pub best_move: Move,
    pub score: i32,          // 红方视角，中分=0
    pub depth: u8, pub nodes: u64, pub time_ms: u64, pub pv: Vec<Move>,
}
pub struct BuiltinEngine { pub depth: u8 }
impl BuiltinEngine {
    pub fn best_move(&self, board: &Board) -> SearchReport;
}
```

- **搜索**：迭代加深 α-β 剪枝 + 置换表（`HashMap<u64, TTEntry>`，key=局面积分哈希，entry 含 depth/score/flag）+ 杀手着法排序 + 基本着法顺序（吃子优先）。
- **评估**：`eval = 子力值 + 位置分`（红方正数）。子力：帅 100000、车 600、马 320、炮 320、士 120、相 120、兵 60（过河 +40 递增）。位置表：兵卒/车/马/炮按九宫与河界加权；预留 `trait Evaluator` 扩展点（未来 NNUE）。
- **确定性**：不用随机，同局面同深度同结果。
- **超时控制**：`best_move_with_timeout(board, ms)` 按节点预算折算（每层检查时间），超时返回当前迭代最佳着。
- **单测**：确定性断言、指定深度杀局命中（如单马擒单士需 ≥6 层，用简化局面验证到杀）、无着可走返回 None 场景、评估对称性（红黑镜像分取反）。

## 4. 统一引擎接口（game-core 内定义）

```rust
pub enum EngineId {
    Builtin { depth: u8 },
    Llm,
    Pikafish,            // 桌面端可用
}

pub struct EngineOptions { pub think_ms: u32 }       // 0 = 不限（内置按深度）
pub struct EngineOutcome {
    pub mv: Move,
    pub source: EngineId,
    pub fallback_reason: Option<String>,   // 降级原因（如 "LLM 超时，已用内置引擎"）
}

pub trait Engine: Send {
    fn id(&self) -> EngineId;
    fn name(&self) -> String;
    fn best_move(&mut self, board: &Board, opts: EngineOptions) -> EngineOutcome;
}
```

- 内置：同步计算（快，直接返回）。
- LLM / 皮卡鱼：内部异步；调用方（机器对战/人机走子命令）在 `tokio::task::spawn_blocking` 或异步运行时中执行，前端经 invoke 等待（机器对战中用 Channel 逐着推送，单着等待不阻塞 UI）。
- `EngineManager`（Tauri managed state）：按 `EngineId` 创建实例；皮卡鱼进程懒启动并复用于整局，对局结束/切换时 drop 终止进程。

## 5. 大模型引擎（llm-engine）

> 完整实现细节（提示词原文、请求参数注意事项、校验过滤链、踩坑记录、其他技术栈参考）见 [大模型引擎设计与对接规范.md](大模型引擎设计与对接规范.md)。

### 5.1 配置
```rust
pub struct LlmConfig {
    pub base_url: String,      // 如 https://api.openai.com/v1 或兼容厂商
    pub api_key: String,
    pub model: String,
    pub timeout_secs: u32,     // 默认 30（前端可调 5–120）
    pub temperature: f32,      // 默认 0.2（求稳定）
}
```
持久化于应用数据目录 `llm-config.json`（Linux 如 `~/.local/share/com.xiangqi.app/llm-config.json`，不写安装目录），启动时自动加载恢复；密钥不随存档导出，UI 密码输入框不回显，空 key 保存/测试时自动沿用已存密钥（不会误清空）；Unix 下文件权限 600。

### 5.2 请求（OpenAI Chat Completions 兼容）
- `POST {base_url}/chat/completions`，头 `Authorization: Bearer <key>`。
- body：`{ model, messages, temperature: 0.2, max_tokens: 512, stream: true, enable_thinking: false }`。
  - `stream: true`：流式 SSE（响应头即时返回，避免非流式等完整生成导致的"能答却超时"）；服务端不支持流式时自动回退 JSON。
  - `enable_thinking: false`：qwen3 系列关闭思考链（默认开启会拖慢响应并占满 max_tokens）。
  - `max_tokens` 不宜过小（曾用 64，思考链会占满导致着法缺失）。
- messages：
  - system：坐标规则 + few-shot 正确示例 + 硬性约束（起点必须是你方棋子所在格；符合行棋规则；仅输出 4 字符 UCCI，禁止解释/标点）。完整原文见《大模型引擎设计与对接规范.md》。
  - user：`FEN: <fen>\n轮走方: <red|black>\n请给出最佳着法。`

### 5.3 解析与校验
- 正则 `[a-i][0-9][a-i][0-9]` 提取；转为 `Move`；必须 ∈ 当前合法着集合。
- 非法：二轮纠错把当前局面**全部合法着清单**发给模型"请只从中选择一步"（把自由推演降级为选择题，命中率接近 100%）；仍非法 → 降级。
- 超时（可配 5–120s，按分块读取计时）/网络错误/HTTP 非 200 → 直接降级。
- 任何情况下最终仍过合法着集合校验，应用永远不会走出非法着。

### 5.4 降级
- 默认兜底：内置引擎（depth 与当前难度一致）。
- 返回 `EngineOutcome { fallback_reason: Some(...) }`，UI 提示"大模型超时/出错，已由内置引擎走子"。

### 5.5 测试与连通性
- 应用内「测试连接」命令 `test_llm_config`：用当前/已存参数发最小请求，返回"连接成功/失败原因"（与真实走子同一套参数与超时，避免"测试通过、实战超时"假象）。
- 单元/集成：用本地 mock HTTP（`axum` 或 wiremock）：正常合法响应 / 含解释的响应 / 非法着 / 超时（服务端延迟 > timeout）/ 500 / 连接拒绝 / SSE 流式分片 → 断言解析与降级路径。
- UI 线程安全：`machine_step` / `test_llm_config` 为 async 命令（LLM 请求在后台执行，不阻塞主线程/UI）。

## 6. 皮卡鱼适配（pikafish-adapter，桌面端）

### 6.1 资源
- `src-tauri/resources/pikafish/<os>-<arch>/pikafish[.exe]` + `pikafish.nnue`。
- 平台矩阵：windows-x64、linux-x64、linux-x64 通用（含 arm64 备选）、macos-x64、macos-arm64。
- 打包：`tauri.conf.json` `bundle.resources` 包含该目录；运行时路径用 `app.path().resource_dir()`。
- 合规：仓库附 `THIRD_PARTY_LICENSES.md`（GPLv3 全文 + 皮卡鱼源码链接），UI"关于"页声明。

### 6.2 UCI 会话协议
```
启动子进程（stdin/stdout 管道）
→ 发: uci\n            → 等回复含 uciok
→ 发: setoption name Threads value 1\n
→ 发: isready\n        → 等 readyok
→ 每步: position fen <fen> moves <uci_moves...>\n
→ 发: go movetime <ms>\n
→ 监听 stdout 直到 bestmove <mv>\n（解析 info 行可忽略）
→ 终止: quit\n
```
- 着法格式：皮卡鱼 UCI 走法为 4 字符坐标串（红方视角 file a-i / rank 0-9），与内部 UCCI 一致，仅需合法性复核。
- **超时保护**：`go` 后 30s 无 `bestmove` → kill 进程、重启会话，返回降级（内置引擎）。
- **进程生命周期**：懒启动（首次调用时）、整局复用、drop 时 `quit` + kill；启动失败（二进制缺失/架构不符）→ 自动回退内置引擎并上报原因。

### 6.3 测试
- mock 子进程（测试内起一个假引擎进程，按 UCI 应答并返回指定 bestmove）：协议握手、解析、超时路径、非法着复核。
- 真实皮卡鱼测试标 `#[ignore]`，需要资源时手动运行。

## 7. 对局状态机（game-core）

```rust
pub enum GameMode { HumanVsMachine, MachineVsMachine }
pub struct Game {
    pub board: Board,
    pub mode: GameMode,
    pub red_engine: EngineId, pub black_engine: EngineId,
    pub moves: Vec<Move>,            // 全量着法（可重建局面）
    pub status: GameStatus,          // Ongoing/Check/Checkmate/Stalemate/Resigned/Draw
    pub move_count: u32,
}
impl Game {
    pub fn new(mode, red, black) -> Self;          // 初始局面
    pub fn apply_human_move(&mut self, mv) -> Result<(), GameError>;  // 校验+应用
    pub fn engine_to_move(&self) -> Option<Color>; // 当前该机器走的方
    pub fn resign(&mut self, color) / undo(&mut self) / restart(&mut self);
    pub fn replay(&self) -> Board;                 // 从 start_fen+moves 重建
}
```

- 机器对战：调度器（在 tauri 命令/后台任务中）循环 `while status == Ongoing`：取当前方引擎 → `best_move` → 应用 → 通过 **Channel** 推送 `{mv, fen, engine, fallback_reason}` → 判定状态；步间可响应暂停/速度（前端控制节奏：引擎算完后先暂停推送，按 1×/2×/4× 定时渲染）。
- 长将/长捉：阶段一实现自然限着 60 回合；重复局面检测留待后续增强（记录为已知限制）。

## 8. 持久化（game-store）

### 8.1 文件布局（`app_data_dir()/xiangqi/`）
- `save_1.json` … `save_5.json`：手动槽位
- `autosave.json`：每步落子 + 退出时写入（崩溃恢复）
- `llm-config.json`（应用数据目录）：LLM 配置（base_url/api_key/model/timeout_secs/temperature）；`settings.json`：用户偏好（默认引擎、难度、步时）

### 8.2 SaveData schema
```json
{
  "version": 1,
  "name": "对局 1",
  "mode": "human_vs_machine",
  "red_engine": { "kind": "builtin", "depth": 4 },
  "black_engine": { "kind": "llm" },
  "start_fen": "rnbakabnr/9/... 0 1",
  "moves": ["h2e2", "h8e8"],
  "result": null,
  "created_at": 1759400000,
  "updated_at": 1759400060
}
```
- 恢复：`autosave.json` → `Game::new` + 重放 moves；`load(slot)` 同理；列表返回名称/时间/状态摘要。

### 8.3 API
`list_saves() / save(slot, name) / load(slot) / delete_save(slot) / autosave() / restore_autosave() / import_fen(fen) / export_fen()`

### 8.4 测试
往返一致性（save→load→重放局面 equals）、损坏 JSON 容错（返回错误不 panic）、5 槽位边界、moves 含非法着时拒绝加载并报告。

## 9. Tauri 集成层（src-tauri）

### 9.1 Commands（全部同步/异步命令，错误用 `Result<_, String>`）
| 命令 | 说明 |
|---|---|
| `get_engines() -> Vec<EngineDesc>` | 平台可用引擎列表（Android 隐藏 pikafish） |
| `new_game(mode, red, black)` | 创建对局 |
| `player_move(mv)` | 玩家走子；若对方是机器 → 后台算子并返回结果（人机单着同步等待可接受：内置 <1s，LLM ≤30s 可调 5–120 + 降级；async 命令在后台线程池执行，不阻塞主线程） |
| `machine_step()` | 机器对战推进一步（配合前端节奏控制） |
| `get_hint()` | 内置引擎当前局面建议着 |
| `undo / resign / restart` | 对局控制 |
| `save / load / list_saves / delete_save / import_fen / export_fen` | 持久化 |
| `get_llm_config / set_llm_config` | LLM 配置（持久化于应用数据目录 llm-config.json，启动自动恢复；另有 `test_llm_config` 测试连接） |
| `get_game_state()` | 前端同步当前对局快照（fen/moves/status/引擎） |

### 9.2 Channel / 事件
- 机器对战：`channel.on("machine-move", ...)`，每着推送 `{mv_ucci, fen, engine, fallback_reason}`。

### 9.3 capabilities（`capabilities/default.json`）
- `core:default`（window/event/ipc 最小集）
- 不向前端开放 `shell`、`fs`、`http` 权限 —— 网络与文件全部在 Rust 端完成，前端仅通过自定义命令交互。

### 9.4 配置文件要点
- `tauri.conf.json`：`identifier: com.example.xiangqi`、`bundle.resources: ["resources/pikafish/**"]`、`bundle.targets`（桌面三平台 + Android `apk`）、产品名"中国象棋"。
- Android：`gen android` 生成模板；`minSdk 24+`。

## 10. 前端设计（React + TS + Vite）

### 10.1 组件树
```
App
├── GameScreen
│   ├── Board (Canvas)
│   │   ├── drawBoard()        # 9×10 网格、河界、九宫、坐标标注

│       ├── 操作：悔棋 / 提示 / 认输 / 新局 / 保存 / 加载 / 导入 FEN

│       └── 状态栏（将军/胜负/降级提示）
└── SettingsModal（LLM：base_url/key/model/超时；偏好默认引擎与难度）
```

### 10.2 状态管理
- `GameState`（前端镜像）：fen、moves、status、当前方、selected、legalTargets。
- 事件流：`player_move` 后 invoke 返回新快照；机器对战走 Channel 事件逐个更新。
- 坐标换算：像素 ↔ `{file, rank}` ↔ sq（与 core 一致的红方视角，棋盘默认红方在下；支持镜像翻转可选）。

### 10.3 渲染与交互
- Canvas 2D 自绘（跨端一致）；点击选中 → 高亮合法目标 → 点击目标走子 → invoke。
- 走子动画：轻量补间（棋子移动 150ms），失败不影响功能。
- 中文棋子文字：`"帥仕相馬車炮兵" / "将士象马车炮卒"`。

### 10.4 前端测试（Vitest）
- 坐标换算单测、合法目标高亮逻辑、状态机 reducer（人机/观战）、引擎选择可见性（平台差异）。
