# 大模型配置指南

本应用的大模型引擎兼容 **OpenAI Chat Completions 协议**（流式 SSE），任何提供该协议的服务均可接入（OpenAI、DeepSeek、豆包/火山方舟、通义千问、Kimi、智谱等）。

> 详细实现（提示词原文、请求参数注意事项、校验过滤链、踩坑记录、其他技术栈实现参考）见 [大模型引擎设计与对接规范.md](大模型引擎设计与对接规范.md)。

## 1. 在哪里配置

- 应用内：主界面 → 设置（齿轮）→ "大模型" 页签
- 字段说明：

| 字段 | 示例 | 说明 |
|---|---|---|
| Base URL | `https://api.deepseek.com/v1` | 服务商 API 根地址（不含 `/chat/completions`，应用自动拼接） |
| API Key | `sk-xxxxxxxx` | 服务商控制台创建的密钥，仅存本机，不回显；**留空保存 = 保留已存密钥**（不会误清空） |
| 模型 | `deepseek-chat` | 服务商支持的模型名 |
| 超时（秒） | `30` | 请求超时上限（可调 5–120，默认 30），超时自动降级内置引擎 |

- 「测试连接」按钮：用当前（或已保存）参数发一次最小请求，验证连通与密钥是否有效，显示"连接成功 / 失败原因"。
- 「保存配置」：持久化到**应用数据目录**（非安装目录），下次启动自动恢复，无需重新输入。

## 2. 常见服务商参考

> 请以各服务商最新官方文档为准；此处仅为常见示例，方便快速填写。

| 服务商 | Base URL | 模型示例 | 获取 Key |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | platform.deepseek.com |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | platform.openai.com |
| 火山方舟（豆包大模型） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-1-6-250615` 等推理接入点 ID | console.volcengine.com/ark |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.8-max` 等 | bailian.console.aliyun.com |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | open.bigmodel.cn |

> qwen3 系列默认开启思考链，应用已通过 `enable_thinking=false` 关闭以加速响应；若服务商/模型不接受该参数导致报错，需按模型调整。

## 3. 工作原理（建议了解）

1. 轮到"大模型引擎"走子时，应用将当前局面编码为 **FEN** 并构造提示词（坐标规则 + few-shot 示例 + "仅输出一步 UCCI 走法"硬性约束）。
2. 请求 `POST {base_url}/chat/completions`（Bearer 认证），**流式 SSE** 接收；`stream=true`、`enable_thinking=false`、`max_tokens=512`、`temperature=0.2`。
3. 解析模型输出 → 提取 UCCI 4 字符 → **与全部合法走法比对**。
4. 输出非法：二轮纠错把**合法着清单**发给模型让其选择；仍非法、或超时、网络错误 → **自动降级为内置引擎**走子，并在界面提示原因。
5. 因此：**无论模型回答什么，应用永远不会走出非法着**。

## 4. 安全与隐私

- API Key 仅存储在本机应用数据目录 `llm-config.json`（Linux 如 `~/.local/share/com.xiangqi.app/llm-config.json`），不会写入对局存档、不会上传；文件权限设为 600（仅本人可读写）。
- 每次走子仅发送当前 FEN 与简短提示词，不发送其他个人数据。
- 请在可信设备上使用；妥善保管密钥。
